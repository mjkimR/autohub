# Technical Plan: `SPEC-owed-item-contract` Owed item contract for operator debt

## 1. Constitution & Invariant Review

- `ADR-owed-items-aggregate-read` decides the read path: one read-only aggregate repository, one `UNION ALL` keyset
  query per page and one `GROUP BY` count per counts read. The plan follows it. Its "adapter check filters a bounded
  SQL candidate set in the service" is realised by evaluating the adapter registry in the service and passing the
  resulting adapter set into the SQL predicate; the candidate filter stays bounded and the page stays one statement.
- `ARCH-02-constraints`: the owed-items router imports only its use case; `RULE-app-router-repo-import` stays clean.
  One `AsyncTransaction` per request, no nesting, no provider call.
- `SPEC-pending-decision-count`: `actionable_total_count` stays unchanged (its Non-goal 5); the owed `decision` count
  reuses the same predicate (actionable row of a non-final run).
- No ADR is needed beyond the accepted one; no migration.

## 2. Architecture Overview & Impact

- New feature package `modules/hub/app/features/project_management/owed_items/`:
  - `schemas.py`: `OwedItemKind`, `OwedItemRead`, `OwedSubject`, `OwedAction`, `OwedContext`, `CatalogHold`,
    `OwedItemPage`, `OwedItemCounts`.
  - `repos.py`: `OwedItemRepository` (read-only aggregate; owner models only, no owner repository import).
  - `services.py`: kind catalogue (counted flag, subject type, action), adapter set for the connection-test
    predicate, cursor encode/decode and row presentation.
  - `usecases.py`: `OwedItemUseCase.list` and `.counts`, each in one `AsyncTransaction`.
  - `api.py`: `GET /owed-items` and `GET /owed-items/counts` with `Annotated[OwedItemUseCase, Depends()]`.
- `modules/hub/app/router.py`: includes the owed-items router under the authenticated v1 router (scope extension).
- `pipeline_runs/models.py`: `PipelineRun.has_pending_decision` read-only `column_property` (correlated `EXISTS`
  over actionable `run_decision_entries`), loaded with the run row in the same statement.
- `pipeline_runs/discovery_projection.py`: the mapper hook sets the flag's committed value on the in-session run after
  it refreshes the projection, so responses built after a flush in the same transaction report the new value.
- `pipeline_runs/schemas.py`: `PipelineRunRead.has_pending_decision: bool = False`.
- `modules/hub-ui/src/lib/api/`: regenerated by `just gen-ui-api`; no screen code.

## 3. Component & Interface Design

```text
GET /api/v1/owed-items?project_id&kind&cursor&limit(1..100, default 50) -> OwedItemPage
GET /api/v1/owed-items/counts?project_id                             -> OwedItemCounts
Router -> OwedItemUseCase -> OwedItemService (kinds, cursor, presentation)
                          -> OwedItemRepository (one UNION ALL page | one GROUP BY count)
```

```python
class OwedItemPage(BaseModel):
    items: list[OwedItemRead]
    has_more: bool
    next_cursor: str | None

class OwedItemCounts(BaseModel):
    total: int                      # counted kinds only
    by_kind: dict[OwedItemKind, int]  # every kind, zero included
    by_project: dict[UUID, int]       # counted items per project, zero omitted
```

Each union branch selects the same columns: `kind`, `sort_key` (`<kind>:<subject id as text>`), `subject_id`,
`project_id`, `waiting_since`, `state`, `detail`, `run_id`, `work_plan_id`, `work_item_id`, `sdd_batch_id`,
`catalog_id`, `catalog_held`. The page orders by (`waiting_since`, `sort_key`) and fetches `limit + 1`. The public
`key` is built in the service from `kind` and the canonical subject ID; on PostgreSQL it equals `sort_key`.

Suppression predicates (correlated `EXISTS`): run held by a decision (any decision row), Work Item with a counted
recovery or replacement, run claimed by a batch in `attention`, Work Item in `attention` for a run, and batch with a
claimed run held by a decision.

## 4. Storage & State Management

No new table or column. The flag is a SQL expression. The owed set is a query-time union; catalog-hold state uses the
request time as a bound parameter.

## 5. Error Handling & Edge Cases

- Unknown `project_id`: HTTP 404 (`ProjectError`), checked inside the same transaction.
- Malformed cursor or cursor with changed filters: HTTP 422, matching the decision cursor rules.
- Out-of-range `limit` or unknown `kind`: FastAPI validation, HTTP 422.
- SQLite stores naive datetimes and hex UUIDs; the service normalises them to UTC-aware datetimes and canonical UUID
  text for the public key.
